## 行为准则

参与本项目时，请遵守以下行为准则：

1. **尊重他人**：无论性别、性取向、残疾、种族、宗教、政治立场、年龄、国籍，都应保持尊重
2. **友善沟通**：使用友善、包容的语言，避免人身攻击和恶意嘲讽
3. **专注项目**：讨论应围绕项目本身，不涉及无关的政治、宗教等敏感话题
4. **保护隐私**：不泄露他人的个人信息，包括 QQ 号、手机号、邮箱等

违反行为准则的行为可能会被项目维护者处理，包括但不限于删除评论、封禁账号等。

## 如何贡献

你可以通过以下方式贡献：

### 🐛 报告 Bug

如果你发现了 Bug，请提交 Issue，包含以下信息：

- **Bug 描述**：清晰描述 Bug 是什么
- **复现步骤**：如何复现这个 Bug
- **预期行为**：你认为应该是什么结果
- **实际行为**：实际发生了什么
- **环境信息**：操作系统、Python 版本、项目版本
- **日志信息**：相关的错误日志（注意脱敏，不要包含 API Key、QQ 号等敏感信息）

### ✨ 提出新功能

如果你有好的想法，欢迎提交 Issue 讨论，包含以下信息：

- **功能描述**：这个功能是什么
- **使用场景**：在什么情况下需要这个功能
- **实现思路**：你打算如何实现（可选）
- **替代方案**：有没有其他实现方式（可选）

### 📝 改进文档

文档也是项目的重要组成部分，欢迎改进：

- 修正错别字和语法错误
- 补充缺失的说明
- 优化文档结构
- 添加示例代码

### 💻 提交代码

如果你想直接贡献代码，请参考下面的开发流程。

## 开发环境搭建

### 1. Fork 项目

在 GitHub 上 Fork 本项目到你的账号下。

### 2. 克隆到本地

```bash
git clone https://github.com/你的用户名/qq-ai-chatbot.git
cd qq-ai-chatbot
```

### 3. 添加上游仓库

```bash
git remote add upstream https://github.com/原作者/qq-ai-chatbot.git
```

### 4. 安装依赖

```bash
cd bot
pip install -r requirements.txt
```

### 5. 配置开发环境

```bash
# 复制配置模板
copy .env.example .env

# 编辑 .env，填入你的测试配置
# 建议使用测试用的 QQ 小号和 API Key
```

### 6. 创建分支

```bash
git checkout -b feature/你的功能名
# 或
git checkout -b fix/你修复的Bug
```

### 7. 运行测试

确保你的修改不会破坏现有功能：

```bash
# 启动机器人测试
cd ..
start.bat
```

在 QQ 群里测试相关功能是否正常。

## 代码规范

### Python 代码

- 遵循 [PEP 8](https://peps.python.org/pep-0008/) 代码风格
- 使用 4 空格缩进，不使用 Tab
- 行宽不超过 120 字符
- 函数和变量使用 snake_case 命名
- 类名使用 PascalCase 命名
- 常量使用 UPPER_SNAKE_CASE 命名
- 添加必要的注释和文档字符串（docstring）
- 导入顺序：标准库 → 第三方库 → 本地模块

### 示例

```python
"""模块说明文档。

详细描述模块的功能和使用方法。
"""

from typing import Optional

import requests


class ExampleClass:
    """示例类。

    详细描述类的功能。
    """

    def __init__(self, name: str, age: Optional[int] = None):
        """初始化。

        Args:
            name: 名称
            age: 年龄，可选
        """
        self.name = name
        self.age = age

    def greet(self) -> str:
        """打招呼。

        Returns:
            打招呼的字符串
        """
        if self.age:
            return f"你好，我是{self.name}，今年{self.age}岁。"
        return f"你好，我是{self.name}。"
```

### 前端代码

- 使用原生 HTML/CSS/JavaScript，不引入额外框架
- CSS 使用类名命名，避免 ID 选择器
- JavaScript 使用 ES6+ 语法
- 添加必要的注释
- 避免全局变量污染

### 配置文件

- YAML 文件使用 2 空格缩进
- .env 文件使用大写字母和下划线命名
- 注释说明配置项的用途和默认值

## 提交规范

### 提交信息格式

```
<类型>(<范围>): <简短描述>

<详细描述>

<关联Issue>
```

### 类型

| 类型 | 说明 |
|------|------|
| `feat` | 新功能 |
| `fix` | 修复 Bug |
| `docs` | 文档修改 |
| `style` | 代码格式调整（不影响功能） |
| `refactor` | 代码重构（不新增功能，不修 Bug） |
| `perf` | 性能优化 |
| `test` | 测试相关 |
| `chore` | 构建/工具/依赖相关 |
| `revert` | 回退提交 |

### 范围（可选）

- `bot`：后端核心
- `console`：Web 控制台
- `personality`：人格系统
- `memory`：记忆系统
- `voice`：语音相关
- `vision`：视觉相关
- `config`：配置相关
- `docs`：文档

### 示例

```
feat(personality): 支持人格切换指令

- 新增 /personality 指令切换人格
- 只有管理员可以切换人格
- 切换后自动保存到配置文件

Closes #123
```

```
fix(memory): 修复长期记忆提取失败的问题

- 修复数据库连接未关闭导致的资源泄漏
- 增加异常处理和重试机制

Fixes #456
```

## Pull Request 流程

### 1. 确保代码最新

在提交 PR 之前，先同步上游仓库的最新代码：

```bash
git fetch upstream
git rebase upstream/main
```

### 2. 检查代码

- 确保代码符合代码规范
- 确保没有引入新的 Bug
- 确保没有硬编码的敏感信息（API Key、QQ 号等）
- 确保文档已更新（如果需要）

### 3. 提交代码

```bash
git add .
git commit -m "feat: 你的功能描述"
git push origin feature/你的功能名
```

### 4. 创建 Pull Request

在 GitHub 上创建 Pull Request，包含以下信息：

- **标题**：清晰描述这个 PR 做了什么
- **描述**：
  - 这个 PR 解决了什么问题
  - 如何实现的
  - 测试了哪些场景
  - 是否有已知的限制或问题
- **关联 Issue**：如果修复了某个 Issue，标注 `Closes #123`
- **截图/录屏**：如果是 UI 相关的修改，附上截图

### 5. 代码审查

项目维护者会进行代码审查，可能会提出修改意见。请：

- 认真对待每一条意见
- 如果有不同看法，可以友好讨论
- 修改后推送新的提交，PR 会自动更新

### 6. 合并

代码审查通过后，项目维护者会合并你的 PR。恭喜你成为贡献者！

## 常见问题

### Q: 我可以提交商业相关的功能吗？

A: 可以，本项目基于 MIT 协议开源，允许商业使用。但请确保你的功能不违反相关法律法规。

### Q: 我的 PR 很久没有被审查怎么办？

A: 可以在 PR 下留言提醒，或者联系项目维护者。请理解维护者可能有自己的工作，需要一些时间。

### Q: 我可以成为项目维护者吗？

A: 欢迎！如果你持续贡献高质量的代码，并且对项目有深入的理解，可以联系项目维护者讨论。

### Q: 提交的代码会被用于商业用途吗？

A: 本项目基于 MIT 协议，任何人都可以自由使用，包括商业用途。你的代码也会遵循同样的协议。

### Q: 我需要签署 CLA（贡献者许可协议）吗？

A: 不需要，本项目不要求签署 CLA。但你需要确保你的代码是你自己原创的，或者有合法的授权。
